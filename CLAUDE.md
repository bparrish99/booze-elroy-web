# Booze Elroy: Web Edition - notes for Claude

Pinback's Pac-Man variant "Booze Elroy" (original: Love2D/Lua, not in this repo). This repo is a faithful JS port, live at booze-elroy.com (Netlify, serves `public/`).

## Rules that matter
- The game logic is canon: gameplay (movement, ghost AI, timing, scoring, levels, RNG calls) must match the original Lua exactly. `src/core.js` started as a 1:1 mirror (Lua truthiness helper `T()`, pinned iteration orders). The *code* has no sentimental value (author, 2026-11-09: refactors and efficiency improvements are welcome); what must not change is behaviour: the same gameplay, frame for frame, and the same user-facing results. Refactor only with that verified: `tests/golden.test.mjs` replays the core (seeded RNG, a pathfinding bot, 13 configurations, 3 minutes each) and compares per-frame state fingerprints with `tests/golden.json`, recorded from master's core before any refactor. Re-record (`node tools/golden.mjs --record`) only when gameplay is *meant* to change, and say so in the commit. Any gameplay change (one the golden replay catches, or a fix to a mode it doesn't cover) also bumps core.js REPLAY_VERSION, so older leaderboard replays are marked as recorded on an older version (they may go out of step).
- Everything around the game (menus, options UX, online features, presentation) is the web edition's own and can move on freely when the author asks; "the Lua did it differently" is not an objection there. Keep such changes in env hooks / leaderboard.js / main.js / render.js where possible, and list them below.
- Deviations from the original (approved by the author):
  - `logic.eatOverlappingFrightened`: a second frightened ghost sharing Pac-Man's tile after an ateGhost pause is also eaten.
  - Bug fix, Plus Mode fruit wins ties (2026-11-13; a bug in the Lua too, fixed here): the fruit frightens the ghosts there like an energizer, so Pac-Man's step now eats it before the ghost collisions, as energizers always were (core.js eatFruit, called early in Plus Mode only; elsewhere it's still eaten after them, unchanged). Before, reaching the fruit and a ghost on the same step got him caught. tests/plusfruit.test.mjs; golden replay unchanged.
  - Scatter: MSPAC matches a real Ms. Pac-Man machine (the author watched one, 2026-11-14): the first switch ends the opening scatter (to chase, reversing), the second reverses them again (still chasing), and after that the timer never reverses them (core.js handleModeSwitching; it used to reverse them at every switch). tests/mspac.test.mjs; the golden replay has no MSPAC game, so it's unchanged.
  - The `large` pack's nonexistent "mega1" maps to "large1" (the original crashes there, likely the cause of old autoplay nil-reference crashes).
  - Online leaderboard (src/leaderboard.js, src/scorekey.js, netlify/): "Leaderboards" main-menu item in the old Exit slot (opens on the current settings' board; left/right or prev/next flip through every board with scores, from GET /api/scores/boards, without touching the player's settings; Share Config there shares the board on show); name entry after a top-10 game over; HIGH SCORE in the header = best for the current gameplay settings (on the Favorites / Pinback's Picks lists: the highlighted one's board, and a favorite's page: its board, scene.headerKey; in a game: the settings in play, borrowed ones too: a pick's, a leaderboard's, an arena's regular board; set when a real game starts, from the cache and again once the board loads, never below the game's own score; the author, 2026-11-16: it used to keep whatever the page before showed) (online leader's name scrolls through the HIGH SCORE field; menu screens refetch the board once their copy is a minute old, so an idle title picks up a new leader without a reload, 2026-11-12); no Reset item in Options: the cheat "reset" (typed on a menu screen) opens a password dialog that resets the online boards (current settings or all). core.js only has small `env` hooks for this (env.scenes, env.afterGameOver, captureInput); without them it behaves like the original.
  - Leaderboard replays (EXPERIMENTAL, the author, 2026-11-18; src/replay.js): every real game is recorded, and a score that makes a top 10 (regular boards and arenas) goes up with its replay; clicking / tapping a score that has one (a little pink play mark by its rank; "▸ replay available" under the list), or pressing its rank's number (1-9, 0 for 10), watches it, then comes back to that page. No video: the game is deterministic, so a replay is the settings (the 13 gameplay ones and starting level, not Pro Mode: watched with the viewer's own, so a pro's game still shows the jingle and the animations to a viewer without), a random seed (real games now draw from a seeded generator, mulberry32, seeded as the game starts: core env.gameStarting; the same randomness, just reproducible) and the inputs: the direction keys held (a bitmask) at each step of play, and every key / button pressed, timed in steps of play only (core env.playStep, each update that reads the controls), so the stretches nobody plays don't matter. Watching re-runs the game in the real renderer at 1x (Space / Enter / tap: 2x, 4x; P pauses; Esc goes back), with "REPLAY" and the player's name top right and a crooked yellow EXPERIMENTAL sticker at the bottom; a replay counts for nothing (no achievements, activity, local best, saved settings; test mode off). Packed as gzip + base64 (a few KB), posted with the score; trust the client, no checking (the author: smaller and easier). Server: their own Blobs store "replays", one per top-10 entry ("r/<rid>"; the entry's rid is shown, GET /api/scores/replay?id= and /api/arenas/replay?id=), deleted when the entry leaves the board (pushed off, replaced by the same name's better arena score), on a reset, an arena deleted or dropped off. For determinism across browsers, Blow's distances use Math.sqrt, not Math.hypot (not guaranteed identical everywhere). tests/replay.e2e.mjs plays real games (from the title, from a leaderboard's Play 1P with Rewind, a 3-life game played with Pro Mode and watched without) and checks each replay ends exactly as its game did; a unit test covers the store's lifecycle. Old scores have no replays.

Playing one applies its settings (starting level 1) until the player leaves (their own come back; never saved).   - Rewind ability (src/rewind.js; ability value 4, "Rewind" in Options; author's design): the ability button plays the last 3 s (180 frames) back at 2x speed (1.5 s on screen), then everything holds still 45 frames where it landed (rewind.js HOLD, about Suck's / Blow's stop, so you see where you are; the author, 2026-11-14), with a VCR look (render.js drawRewindTape: torn bands, static, a blinking rewind sign; shows in every look), then play resumes. One charge, refilled at every READY (new life, new board); Pac-Man goes hollow once it's spent, like any ability that isn't ready (only after the playback: he stays full while it rewinds); activation plays the abilities' "phase" sound. History is only kept in normal play and dropped whenever play stops, so death, level ends and READY can't be rewound; with less history it rewinds what there is. Everything rewinds (score, lives, dots, ghosts, timers), restored *in place* (characters' closures point at their objects); the RNG doesn't. core.js: `ability()` reports Rewind as Off to every gameplay check, `env.rewind` on the button, `resyncLoops()` for the sounds afterwards. tests/rewind.test.mjs checks that a rewind restores every gameplay field on g.
