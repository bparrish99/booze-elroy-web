# Booze Elroy: Web Edition - notes for Claude

Pinback's Pac-Man variant "Booze Elroy" (original: Love2D/Lua, not in this repo). This repo is a faithful JS port, live at booze-elroy.com (Netlify, serves `public/`).

## Rules that matter
- The game logic is canon: gameplay (movement, ghost AI, timing, scoring, levels, RNG calls) must match the original Lua exactly. `src/core.js` started as a 1:1 mirror (Lua truthiness helper `T()`, pinned iteration orders). The *code* has no sentimental value (author, 2026-11-09: refactors and efficiency improvements are welcome); what must not change is behaviour: the same gameplay, frame for frame, and the same user-facing results. Refactor only with that verified: `tests/golden.test.mjs` replays the core (seeded RNG, a pathfinding bot, 13 configurations, 3 minutes each) and compares per-frame state fingerprints with `tests/golden.json`, recorded from master's core before any refactor. Re-record (`node tools/golden.mjs --record`) only when gameplay is *meant* to change, and say so in the commit.
- Everything around the game (menus, options UX, online features, presentation) is the web edition's own and can move on freely when the author asks; "the Lua did it differently" is not an objection there. Keep such changes in env hooks / leaderboard.js / main.js / render.js where possible, and list them below.
- Deviations from the original (approved by the author):
  - `logic.eatOverlappingFrightened`: a second frightened ghost sharing Pac-Man's tile after an ateGhost pause is also eaten.
  - The `large` pack's nonexistent "mega1" maps to "large1" (the original crashes there, likely the cause of old autoplay nil-reference crashes).
  - Online leaderboard (src/leaderboard.js, src/scorekey.js, netlify/): "Leaderboards" main-menu item in the old Exit slot (opens on the current settings' board; left/right or prev/next flip through every board with scores, from GET /api/scores/boards, without touching the player's settings; Share Config there shares the board on show); name entry after a top-10 game over; HIGH SCORE in the header = best for the current gameplay settings (online leader's name scrolls through the HIGH SCORE field); no Reset item in Options: the cheat "reset" (typed on a menu screen) opens a password dialog that resets the online boards (current settings or all). core.js only has small `env` hooks for this (env.scenes, env.afterGameOver, captureInput); without them it behaves like the original.
  - Arenas (src/leaderboard.js scenes "arenas"/"arena", netlify/lib/arenas.mjs, Blobs store "arenas"): 24-hour boards with fixed gameplay settings; main-menu "Arena" under Play 1P. Playing one applies its settings (starting level 1) until the player leaves (their own come back; never saved). Game over in an arena posts to the arena board and the regular board; quitting an arena game (Esc / the X button) goes back to that arena's page (env.quitGameTo). Arena boards keep one entry per name (a better score replaces it; a worse one doesn't place). Finished arenas stay listed 24 h with their winner. 15 min grace for scores after closing. "Share Arena" copies `?arena=<id>`, which opens that arena's page (an expired or unknown one: the arena list, with a "that arena has ended" toast; a network failure just shows the list).
  - Cheat codes (main.js CHEATS): "mina" on menu screens plays the intermission 3 film; "delete" on an arena page opens the password dialog (admin) to delete that arena; "xyzzy" on menu screens toggles test mode (off by default, remembered in localStorage "booze-elroy-fps"): a small FPS readout (#fps, bottom right of the window), and Pro Mode always on (env.testMode).
  - Leaderboards page: "PLAY 1P" plays the board on show with its gameplay settings (own starting level), borrowed like an arena's until the player leaves the leaderboard (LB playingBoard / ownConfig; never saved). Quitting or finishing that game comes back to that board (env.quitGameTo / afterGameOver).
  - Rewind ability (src/rewind.js; ability value 4, "Rewind" in Options; author's design): the ability button plays the last 3 s (180 frames) back at 2x speed (1.5 s on screen) with a VCR look (render.js drawRewindTape: torn bands, static, a blinking rewind sign; shows in every look), then play resumes. One charge, refilled at every READY (new life, new board); Pac-Man goes hollow once it's spent, like any ability that isn't ready (only after the playback: he stays full while it rewinds); activation plays the abilities' "phase" sound. History is only kept in normal play and dropped whenever play stops, so death, level ends and READY can't be rewound; with less history it rewinds what there is. Everything rewinds (score, lives, dots, ghosts, timers), restored *in place* (characters' closures point at their objects); the RNG doesn't. core.js: `ability()` reports Rewind as Off to every gameplay check, `env.rewind` on the button, `resyncLoops()` for the sounds afterwards. tests/rewind.test.mjs checks that a rewind restores every gameplay field on g. Share codes: the 6-character format is frozen (scorekey LEGACY_LENGTHS); Rewind configs get 7-character codes; board keys of the old values are unchanged.
  - Options page: "Create Arena" (env.createArena) names a new arena with the current settings; Esc there returns to Options.
  - Pro Mode (Options > STYLE, the section once called VIDEO; `proMode`, off by default; env.proMode adds the row): real games (not the attract demo) skip the opening jingle / PLAYER ONE, the death animation (caught -> READY), the board-complete flashing (a 45-frame pause, then the next board) and so the intermissions; READY is 45 frames instead of 120 (core.js pro()). Nothing of it runs during play, so it isn't in the board key (like the other Style settings; Restore Defaults keeps it). tests/promode.test.mjs.
  - Boost doesn't tint Pac-Man green (the Lua did; it no longer fit): he stays plain yellow while boosting, hollow while it reloads (render.js).
  - Elroy's bubbles are drawn as pixel-art cartoon bubbles by render.js (render-only life/motion); core still emits the same particles with the same RNG calls (`bubble: true` flag only). The bubbles are dropped whenever the core replaces g.particles with a fresh list (new game, death, board done), so the title's/demo's bubbles don't float into a new game.
  - "OY" easter egg: clicking/tapping the wall block round "OY" (pac and large1 mazes, while drawn) plays `assets/sounds/oy.mp3` at sfx volume (also in the attract demo, which mutes the game: uses g.originalVolume) (render.js oyBlock, main.js pointerdown). build.py bundles sounds/*.mp3 as well as *.flac.
  - "Share Config" (Options and the Leaderboard page; env.shareConfig / LB opts.share): copies `https://booze-elroy.com/?cfg=<6-char share code>` (scorekey.js shareCode: scrambled, with a check digit) and shows a "link copied to clipboard" popup (g.toast); opening such a link preselects those gameplay settings (not starting level or Audio/Video) and saves them.
  - Maze editor (tools/maze-editor; private dev tool, never deployed: `npm run dev`, then http://localhost:8888/editor/): 28x31 mazes with the standard pen; a new maze starts as a copy of pac (the arcade maze) to change from there; the right button paints the opposite of the tool (dots with Wall, wall with a path tool). Tried and dropped: starting from solid wall, and a "connect the dots" 3-tile grid (the arcade has 3-tall walls, which a grid of 2-thick walls can't make) (fixed, with its no-dot ring and Pac-Man's start), left/right mirrored; wall glyphs are auto-tiled (autotile.mjs: quarter-tile fill rule + a glyph table learned from the existing mazes in data.json; the Glyph tool picks among the glyphs that fit, the After Dark tool sets which walls stay visible). Tunnels (`_`, both edges), no-dot paths, energizers, restricted no-up tiles (`;` / `:`). Scatter targets per ghost (presets "off the maze" / "inside", or each picked on the maze or typed in, off-maze allowed; drawn as ghost-coloured crosshairs). Checks: walls under 2 thick, unreachable dots, one-sided vertical tunnels, dead ends, extra-ghost starts. Drafts in `mazes/<name>.json`; "Add to game" writes `assets/data.json` and rebuilds. Open > Edit opens a game maze itself (booze1, pac, ...; "Update in game" writes it back, merged into its entry): a colour change goes straight through; a layout or settings change asks first (it changes how that maze plays, and its old scores were set on the old version). Open > Copy starts a new maze (booze5, ...) from one. Mazes named booze5, booze6, ... join the booze pack and Normal after booze4 (core.js mazePacks; the Options pack texts count them); they also come up in All. Test play: main.js `?testmaze` (localhost only) plays the maze the editor left in localStorage "booze-elroy-editor-test" whatever the pack (env.testMaze), leaderboards off. Every standard-pen maze opens in the editor and exports back character for character (tests/maze-editor.test.mjs).
  - The "random" maze pack is shown as "all" (the value is still "random": saved settings, share codes and board keys unchanged).
- No music and no music option. No volume option either (env.fixedVolume: the game plays at volume 8; a saved volume is ignored; the browser / system volume does the rest). The Options heading is "STYLE" (Background, Maze Style, Pro Mode). Main menu is Play 1P / Arena / Options / Leaderboards, a blank row apart. No Exit or Autoplay menu items (autoplay code kept; env.noAutoplay). Main-menu and Options action items are centred (env.centerMenus). Options > Restore Defaults leaves the Audio/Video settings alone (env.restoreKeepsAV). Credits is on the Options page (env.creditsInOptions; its Back/Esc return there) and "web edition" on the title links to it. No "click to play" overlay; title shows immediately.
- Title tag text is "WEB EDITION" (bottom row, pink). Full screen is the page button / `F`, not an option. Top-left controls, left to right: volume, look (TV), fullscreen. Volume is the speaker button (click mutes/unmutes; also `M` during gameplay only: on menus M is a letter in cheat codes like "mina") with a vertical slider dropping down below it on hover (touch: the first tap shows it, a second tap mutes); 0-100, squared into a master gain in audio.js (setMaster) and scaled into the film's video volume, remembered in localStorage "booze-elroy-volume" / "booze-elroy-muted"; unmuting at 0 comes back at 50; the game's own volume logic is untouched. The look ("Visuals" in its hover text) is the `C` key or the TV button next to mute (phones have no C key), not an option (env.crtKey removes the CRT EFFECT row): it cycles config.crtEffect true (CRT, default) -> false (plain) -> "tv" (a ratty old living-room TV on an RF cable: render.js rfTV, colour bleed and drift, ghosts, faint crawling diagonal interference, a gentle wave, a torn tracking band drifting down unevenly, and random smooth wonkiness: pulls (a strip of rows bends sideways, quick and jerky), flagging (the top rows flap sideways like a flag), scratchy interference in the rows they bend, a lean, slight width breathing; a little dimmer and more saturated so Pinky stays pink; its bezel is the CRT's (same texture and reflection, baked in pZ), just dark brown (1982 wood panelling)) -> true. Tried and rejected: a green-screen monochrome look, vertical-hold jumps/rolls ("too cheesy"), snow, random block tears / colour cut-outs / per-line jitter ("too spastic"), blotchy/nicotine-stained, tan or light-grey cabinets. Saved at once into the player's own settings (kept when borrowed arena/leaderboard settings are handed back). "Play 1P" is the wording everywhere (main menu, arena page, leaderboard page). The mouse cursor is never hidden (not even in gameplay).
- The "max CRT" look (WebGL presenter in `render.js`) is canon, plus web-edition glass: sheen from the upper right, a soft glint that is secretly the hour hand of a clock whose face is the upper-right window reflection (player's local time: top at 12, right at 3; don't "fix" it, and don't advertise it), and a wider glossy bezel (plain grey plastic, no weathering: tried and rejected) reflecting the screen edges (faint top/bottom so the text rows stay clean; CRT_ZOOM is shared with main.js toGame for clicks). With CRT on, the bezel fills the window: the live WebGL canvas is only the screen plus a margin (main.js MARGIN) for the rim reflections, and the rest is a static image on `#bezel` behind it. The bezel's static look (pZ) is baked once per resize over the whole window and never recomputed per frame (performance: keep per-frame work to the screen-sized canvas). CRT off = the game-sized canvas. Backgrounds are pre-darkened to 25% brightness.
- Visual restraint: the game itself stays plain, pixel-perfect Pac-Man. Effects belong only to the CRT/glass/bezel layer, and should be subtle; CRT off = the untouched picture.
- Ability not ready ("out of gas": Phase/Boost reload, Stun's cycle, Rewind spent): Pac-Man is drawn hollow: a darker yellow at his edge fading smoothly (by distance from the edge, smoothstep over 3 px) to a very dark yellow in the middle (render.js setHollow / hollowFrame, baked once per frame of the sprite), replacing the original flat darker-yellow tint. Tried and rejected: a crisp 1-pixel outline round a flat dark fill (replaced by the fade), palette-cycled stripes, spirals, yellow static, a white glint while ready.
- The autoplayer (attract demo, autoplay) uses Rewind when a ghost gets too close, like the other abilities.
- Menu moves on the web edition's own pages (leaderboard, arenas, arena, name-entry grid) and mouse hover alternate wakka1/wakka2 like the core menus (LB.wakka, sharing g.wakka).
- Options and high score are saved in localStorage.
- Intermission 3 plays `assets/video/mina.*` (a dedication to the author's daughter). Treat it with care; it only works in real browsers.
- Credits: "pinback" pulses colours and links to a mailto; the bottom marquee ("what is seeing this?", one pass every ~2 s gap; "?" only exists in font colour 3) links to https://pinback.substack.com.

## Workflow
`npm run build` -> `public/index.html` (commit it). Node 24 via nvm (`.nvmrc`; system Node is an old 12, so `. ~/.nvm/nvm.sh` first). `npm run lint` (ESLint 9, must stay clean), `npm test` (unit + golden replay + rewind + smoke + leaderboard/arena e2e). `npm run dev` = local preview with the API. `assets/` was generated once by `tools/prep_assets.py` from the original source (needs Pillow, ffmpeg and BOOZE_SRC). The Lua is over (author, 2026-11-09): `assets/data.json` is now edited by the maze editor, so don't re-run `tools/export_data.py` (it would drop the editor's mazes).
Verification against the original was done with a headless Lua-vs-JS trace diff kept outside this repo.

## Leaderboard
Netlify Function `netlify/functions/scores.mjs` + Netlify Blobs store "leaderboard", one JSON blob per settings combination (key from `scorekey.js`: 13 Game/Player/Ghost options; starting level and Audio/Video options never count). Top 10, names up to 16 chars (A-Z 0-9 ! - / space: the font has no "?" or "."), trust-the-client. Reset password: Netlify env var LEADERBOARD_ADMIN_PASSWORD. `npm run dev` previews locally (password "dev").
